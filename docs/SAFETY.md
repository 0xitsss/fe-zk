# fe-zk safety rules: where each is enforced and tested

This file maps every safety rule from `CLAUDE.md` section 3 to the code that enforces it and the
test that would fail if the check were removed. File and line references were regenerated by grep against
the code of v0.2.0 (the verifier API of `docs/API.md`); paths are relative to the repository root.
"Generated" tests are the tests emitted by `fe-zk-gen` next to the generated verifier (see section 9), e.g.
`examples/membership/verifier/src/tests.fe`. Sections 10 to 13 cover what v0.2.0 added: the failure rule,
`fe_zk::anon`, the Semaphore ingot and the Tornado verifier.

## 7. No unchecked arithmetic on untrusted values

All field arithmetic goes through `addmod` / `mulmod` on canonical values (`src/field/fp.fe`). `Fp::sub`
relies on `other.v < P` (`src/field/fp.fe:70`-`:73`, bound stated in the comments there; `Fp` values are
canonical by construction). Every `#[arithmetic(unchecked)]` in `src/hash/` (`poseidon2.fe`; the generated
`poseidon_unrolled.fe` and `poseidon2_unrolled.fe`) states its bound next to the code (lazy
reduction bounds, `docs/DESIGN.md` "Hash gas"). Tests: the fast paths equal the checked references at maximal
inputs (`src/tests/hash.fe` `poseidon_fast_equals_reference`, `poseidon2_fast_equals_generic`) and the constant
tables are canonical (`poseidon_tables_are_canonical`, `poseidon2_tables_are_canonical`). The Groth16, PLONK, KZG
and halo2 verifiers have no `unchecked` arithmetic; their calldata words enter only through the checked constructors of rules 1 to 3.
The FRI/STARK verifier (`src/verifier/fri.fe`, `fri/merkle.fe`, `field/ext.fe`, `field/fp.fe`) uses `#[arithmetic(unchecked)]` for gas on
KoalaBear values, each with its bound in the doc comment: `Ext4::mul_lazy` (`p, W < 2^64`, sums `< 2^195`), `noncanonical` and
`words_canonical` (`v + 0xffffff` may wrap only when `v >= 2^31`, which the first term already flags), `dot6`, `leaf8`,
`horner_final` (values `< p < 2^31`, sums `< 2^68`), `check_query` (`params_valid(c)` first; lanes `< 2p`, products `< 2^64`),
`climb_path`/`load`/`rd` (range asserted once before the pointer reads). Every proof word is range-checked (`< p`) before
it enters this arithmetic (rule 1 row for FRI above). Tests: `src/tests/fri.fe` `ext_mul_extreme_coefficients` (all coefficients
`p - 1`), the Plonky3 vectors for the extension field and the real-proof suites in `src/tests/fri_suite.fe`.
Calldata words enter only through the checked constructors of rules 1 to 3. The only
shifts on untrusted values are `hash_to_field` (`src/anon/hash.fe:9`, a right shift of a hash, cannot overflow) and the
depth shifts of `LeanImt` (`src/anon/lean_imt.fe:20`, `depth` is capped below 32 first, section 11).

## 8. Malleability

Groth16 proofs are malleable: anyone can re-randomize `(A, B, C)` into another valid proof for the same
public inputs. The membership example records the `nullifierHash` public input, never the proof or its hash.
Code: `examples/membership/src/lib.fe:11`-`:15` (rule stated), `examples/membership/src/lib.fe:140` (`assert(external_nullifier == store.scope)`:
the external nullifier is fixed per contract, so one member cannot mint a fresh nullifier per call), `:142` and
`:154` (`nullifiers[nullifier_hash]` checked before the proof and set only after it verified; only the nullifier
hash is stored). Tests: `examples/membership/src/tests.fe` `proof_flow_unknown_root_tampering_and_replay` (a
failed attempt does not burn the nullifier; a replay with the same nullifier is rejected) and
`proof_for_another_scope_rejected` (a valid proof for another external nullifier is rejected). The generated verifiers state the malleability in their header
(`gen/fe-zk-gen/src/emit.rs`). `examples/life` stores the end board, not a proof or proof hash. The anonymous examples
(section 11) and the Tornado verifier (section 13) follow the same rule: they store the nullifier, never a proof.

## 10. The failure rule: invalid is `false`, lack of gas is a revert

An invalid proof makes a verifier return `false`. Running out of gas must never look like that: a precompile
that runs out of gas fails exactly like one that rejected its input, and `groth16::verify` maps a failed pairing
call to `false` (so that a `B` outside the subgroup is a clean `false`). Without a guard, a caller could starve the
call and get "proof rejected" for a valid proof.

| Where | How | Test |
|---|---|---|
| `src/ec/precompile.fe:14` `GAS_MARGIN` = 5000, `:20` `require_gas(cap)` | `assert(ctx.gas() >= cap + GAS_MARGIN)` before every precompile call: `call_try` (`:61`), `call_try_fixed` (`:121`), `call_try_fixed_buf` (`:147`); `call_checked` goes through `call_try`. This covers 0x02, 0x05, 0x06, 0x07, 0x08, 0x0a to 0x11 | `src/tests/failure_rule.fe` `groth16_low_gas_reverts`, `groth16_just_short_of_gas_reverts` (mutation-sensitive: they fail if the guard is removed), `groth16_invalid_with_gas_is_false` |
| `src/verifier/groth16.fe:93` | a degenerate (poisoned) key makes `groth16::verify` return `false` before any gas check or precompile call | `src/tests/failure_rule.fe` `groth16_degenerate_key_never_verifies`; generated `poisoned_keys_reject_every_proof` (gnark) |
| PLONK, gnark, halo2: strict `pairing_check` | a failed call reverts anyway, so these tests also pass without the guard; they pin the revert behaviour, not the guard | `src/tests/failure_rule.fe` `plonk_low_gas_reverts`, `plonk_just_short_of_gas_reverts`, `plonk_invalid_with_gas_is_false`, `gnark_low_gas_reverts`, `gnark_just_short_of_gas_reverts`, `gnark_invalid_with_gas_is_false` |

Consequence for callers: every function that reaches a precompile declares `uses (call: Call, ctx: Ctx)`, and a
caller that wraps a verifier must forward at least `cap + GAS_MARGIN` at each call (about 215,000 gas at the
4-pair pairing). Tight fixed gas limits in a caller revert.
